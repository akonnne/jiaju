## 1. P0 架构级问题（影响落地与合规，必须修）

### 1.1 缺全局「审计日志」模块（audit_log 表无后台入口）— ✅ 已修复（v2.2）
- **现状**：数据库 16 张表统一携带 5 审计字段，`audit_log` 表也已设计；但后台仅在「用户详情抽屉」里有一小段局部日志，**全局无「操作日志/审计日志」菜单**。
- **企业级标准**：系统管理分组下必须有「操作日志」页：操作人 / 操作类型（登录/增删改/导出）/ 模块 / IP / 操作时间，支持按人、按模块、按时间范围筛选，重要操作（删除、权限变更、导出）高亮，支持导出。
- **修改建议**：新增菜单「操作日志」（data-perm="audit"），列表页 + 筛选 + 详情抽屉；示例数据 8~10 条覆盖 登录/发布/删除/导出/改密 等类型。
- **v2.2 落地**：系统管理分组新增「操作日志」（data-perm="audit"，仅 system 可见）；8 种操作类型带色标签（登录/新增/发布/修改/删除/导出/权限变更/密码修改，敏感高亮）；类型/模块/时间筛选 + 导出（导出本身追加审计）；AUDITS 12 条示例。

### 1.2 缺「数据统计报表」页（page_view_log 表无后台入口）— ⏸ 暂缓（主人决策）
- **现状**：工作台只有 Top 5 榜与 7 日趋势，无统计明细页；`page_view_log`（按天聚合）表已设计但无对应页面。
- **企业级标准**：独立「访问统计」菜单：时间范围选择（7/30/90 天）、PV/UV 双指标、按页面类型（首页/产品/新闻/职位）维度下钻、趋势图 + 明细表 + 导出。
- **修改建议**：新增菜单「访问统计」（data-perm="stats"），图表面板 + 维度 Tab + 明细表格。
- **v2.2 状态**：主人明确「数据后台（统计报表页）先不做，后续自接数据库」，本轮不实现；PRD 模块 J 数据统计以工作台 KPI/趋势/排行覆盖。

### 1.3 身份证号明文展示（隐私合规风险）— ✅ 已修复（v2.2）
- **现状**：用户管理列表与详情抽屉中，身份证以 18 位明文展示（如 `330102199001010001`）。
- **企业级标准**：个人敏感信息必须**脱敏展示**（`330102********0001`），详情页默认脱敏、需点击「查看」二次授权才显示全量；按《个人信息保护法》要求最小化展示。
- **修改建议**：渲染时统一脱敏（保留前 6 后 4），抽屉加「查看完整号码」授权按钮；手机号同样建议脱敏（`138****8000`）。
- **v2.2 落地**：列表 `maskPhone` / `maskIdCard` 脱敏 + 行内眼睛图标切换明文/脱敏 + 抽屉「查看」按钮，授权查看 Toast 提示写入 audit_log；原型 USERS 保留明文（接库后按权限控制）。

### 1.4 登录页安全要素缺失 — ✅ 已修复（v2.2）
- **现状**：登录仅 用户名 + 密码 + 角色选择，无验证码、无失败锁定、无「记住我/忘记密码」。
- **企业级标准**：图形/滑动验证码（防暴力破解）、连续失败 N 次锁定 + 冷却、记住我（7 天）、忘记密码（邮箱/短信重置）、登录安全提示（上次登录 IP/时间）。
- **修改建议**：登录卡片加验证码占位 + 记住我 + 忘记密码链接；登录成功 toast 显示「上次登录 IP 与时间」。
- **v2.2 落地**：SVG 随机验证码（点击刷新、防混淆字符集）+ 记住我（7 天）+ 忘记密码（演示占位）+ 连续 5 次错误锁定 30 分钟（对应 PRD G-06）+ 上次登录时间/IP Toast。

## 2. P1 设计系统问题（影响体验与可用性，建议修）

### 2.1 表单校验无反馈（错误态缺失）
- **现状**：表单仅红色 `*` 标必填，无「必填未填 / 格式错误 / 长度错误」的红框 + 提示语，也无通过态反馈。
- **企业级标准**：失焦即校验（blur）、错误红框 + 下方错误文案、通过后绿色对勾、提交时滚动定位首个错误字段。
- **修改建议**：抽一套 `.field.error input` 样式 + JS 校验函数（用户名纯数字、手机号 11 位、身份证 15/18 位、密码强度），至少覆盖用户表单。

### 2.2 页面三态缺失（无加载态 / 错误态）
- **现状**：仅有 banner 空态（`.empty`），列表切换无骨架屏，无「加载失败 + 重试」态。
- **企业级标准**：初次加载骨架屏（skeleton rows）、接口失败错误态（错误图标 + 重试按钮）、空态三件套齐全。
- **修改建议**：抽 `.skeleton` 行样式（3~5 条灰条），切换页面时显示 300ms 骨架；错误态 + 重试按钮组件。

### 2.3 表格能力缺失
- **现状**：表头 `↕` 排序图标为装饰（不可点）；无列配置（显示/隐藏列）、无密度切换、无合计行、无冻结操作列。
- **企业级标准**：列排序（升/降/还原）、列设置抽屉（勾选显隐）、紧凑/默认密度切换、长表冻结首列与操作列、数值列合计。
- **修改建议**：排序图标接 `data-sort` 排序逻辑；工具栏加「列设置 + 密度」下拉；用户表冻结操作列。

### 2.4 顶栏全局搜索与通知为装饰
- **现状**：全局搜索框回车只弹 toast；通知铃铛带角标但无下拉面板。
- **企业级标准**：搜索下拉即时结果（产品/用户/部门/新闻分组列出 + 回车跳转）；通知中心面板（未读列表 + 全部已读 + 点击跳转）。
- **修改建议**：搜索下拉（静态演示 4 类结果）；通知面板抽屉（3~4 条示例）。

### 2.5 侧边栏无二级菜单与收起状态记忆
- **现状**：菜单全一级平铺；折叠后刷新即恢复展开态（无 localStorage 记忆）。
- **企业级标准**：内容管理/系统管理等可二级展开（子菜单缩进）；折叠状态持久化（localStorage）。
- **修改建议**：折叠状态写入 localStorage，刷新保持；可选二级子菜单演示。

### 2.6 辅助文字对比度不足（可访问性）
- **现状**：`--ink-4:#B9B1A5` 用于说明性文字，对比度约 2.6:1，低于 WCAG AA 4.5:1。
- **企业级标准**：正文辅助文字 ≥ 4.5:1；仅纯装饰性内容可低于此。
- **修改建议**：`--ink-4` 加深至约 `#9A9186`（3.0+）或用于非关键处；关键说明用 `--ink-3`。

### 2.7 无键盘焦点样式与无障碍支持
- **现状**：无 `:focus-visible` 样式、无 aria 属性（弹窗/抽屉无 role、无焦点陷阱）。
- **企业级标准**：全站 `:focus-visible` 焦点环；弹窗打开聚焦、Esc 关闭、焦点陷阱；表格/表单标签关联。
- **修改建议**：全局 `*:focus-visible{outline:2px solid var(--primary);outline-offset:2px}`；弹窗 Esc 关闭 + 打开聚焦。

### 2.8 面包屑不可点击
- **现状**：面包屑为纯文本（`<b>工作台</b>`），不可回跳上一级。
- **企业级标准**：面包屑可点击逐级回退（一级可点，末级加粗）。
- **修改建议**：拆分为「总览 / 工作台」两段，前段可点击回 dashboard。

### 2.9 用户管理列表过密（11 列横向滚动）
- **现状**：用户表 min-width 1180px 横向滚动，身份证/地址长文挤压。
- **企业级标准**：瘦身列表（用户名+姓名、性别、部门、角色、状态、最后登录），手机号/身份证/地址收进详情抽屉或悬浮展开。
- **修改建议**：列表瘦身为 7 列，长字段进抽屉。

### 2.10 权限开关无「脏状态」提示
- **现状**：角色页调整权限开关后直接点「保存权限」即 toast，无未保存提示。
- **企业级标准**：开关变更后顶栏/按钮显示「未保存的更改」，离开前拦截确认。
- **修改建议**：监听 switch 变更 → 保存按钮变高亮「保存修改 (n)」；切角色时提示未保存。
